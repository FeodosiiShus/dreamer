# Xcode / Swift Testing speed research for `dreamder/`

Scope: official Apple and Swift sources only. Local tool facts were read with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` (Xcode 27.2, build 27B52). No build, test, lint or formatter was run. The only commands run were help, man, strings and read-only `xcresulttool`/`xccov`/`plutil`/`lipo` calls on existing artifacts. One `xcresulttool merge` wrote to `/tmp` (deleted afterwards).

Legend: **[OBS]** = observed on this machine in a shipped Xcode file or an existing repo artifact. **[INFERENCE]** = my conclusion, not stated by an official source. **Not documented** = no official source found.

Short names used for sources:
- `man xcodebuild` and `xcodebuild -help` = local Xcode 27.2 text. They are not available for Xcode 26.6; items that exist only in 27.2 are flagged.
- `man 5 xcodebuild.xctestrun` = local man page, format version 2.
- RN-x = `https://developer.apple.com/documentation/xcode-release-notes/xcode-<x>-release-notes`.
- ST-docs = `https://developer.apple.com/documentation/testing/...` plus the same text in `https://github.com/swiftlang/swift-testing/tree/main/Sources/Testing/Testing.docc`.

## Q3. Swift Testing's own parallelism

| Item | Official statement | Source |
|---|---|---|
| Default | "By default, tests run in parallel with respect to each other. Parallelization is accomplished by the testing library using task groups, and tests generally all run in the same process. The number of tests that run concurrently is controlled by the Swift runtime." | `https://developer.apple.com/documentation/testing/parallelization` |
| `.serialized` | "When applied to a test suite, this trait causes that suite to run its contained test functions and sub-suites serially instead of in parallel. ... recursively applied ... This trait doesn't affect the execution of a test relative to its peers or to unrelated tests." Applied to a non-parameterized function it has no effect. "Fixed: When applying the `.serialized` trait to a parameterized Swift Testing `@Test` function directly, its cases will be executed serially." (26.0) | same; RN-26 |
| Global disable | "This trait has no effect if test parallelization is globally disabled (by, for example, passing `--no-parallel` to the `swift test` command.)" That is the only documented global switch, and it is a `swift test` (SwiftPM) flag. `xcodebuild -help` lists no equivalent. | same |
| Cap on parallel width | Not documented in the public docs. Source: `Documentation/EnvironmentVariables.md` lists `SWT_EXPERIMENTAL_MAXIMUM_PARALLELIZATION_WIDTH` (`Int`, "The default parallelization width when parallelized testing is enabled") and `SWT_EXPERIMENTAL_SERIALIZED_TRAIT_APPLIES_GLOBALLY`, under the warning "This document is not an API contract. The SPI `Configuration.maximumParallelizationWidth` is `@_spi(Experimental)`. Present in `release/6.3` (`swift-6.3-RELEASE` tag has the file text; the 6.1/6.2 tags 404 on that path) and **[OBS]** the strings `SWT_EXPERIMENTAL_MAXIMUM_PARALLELIZATION_WIDTH`, `--experimental-maximum-parallelization-width` exist in Xcode 27.2's `Testing.framework`. Xcode 26.6 (Swift 6.3) [INFERENCE] has it too; verify with `strings`. Pass it through xcodebuild as `TEST_RUNNER_SWT_EXPERIMENTAL_MAXIMUM_PARALLELIZATION_WIDTH=<N>` ("TEST_RUNNER_<VAR> ... passed, with its prefix stripped, to all test runner processes", `man xcodebuild`). [INFERENCE] it limits concurrently running test cases across all suites, but not tests waiting inside a suite-scope trait such as `.uiGate`. | `https://github.com/swiftlang/swift-testing/blob/main/Documentation/EnvironmentVariables.md`; `.../Sources/Testing/Support/Serializer.swift`; `.../Running/Runner.swift` (549-552); `.../Running/Configuration.swift`; `.../ABI/EntryPoints/EntryPoint.swift` (400-401, 496-499) |

## Do not use

| Option | Why (official evidence) |
|---|---|
| `-parallel-testing-enabled YES`, `-parallel-testing-worker-count`, `-maximum-parallel-testing-workers` as a Swift Testing speedup | Official semantics: "distributing the test classes in a target across multiple runner processes" (RN-10, WWDC20 10221). Swift Testing "runs in-process using Swift Concurrency" (WWDC24 10179) and XCTest is the framework that "only supports parallelization using multiple processes" (WWDC24 10195). No official source says Swift Testing suites are partitioned across runner processes (Not documented). Each runner would also carry its own host app, `.uiGate`, and Dreamder defaults domain [INFERENCE]. Xcode 16.3 known issue: stalls "with debug executable and parallel testing enabled against the Mac run destinations". |
| `-parallelize-tests-among-destinations`, `-maximum-concurrent-test-device-destinations`, `-maximum-concurrent-test-simulator-destinations`, `-disable-concurrent-destination-testing` | Only apply when several destinations are given; the project has one macOS destination (`man xcodebuild`). |
| `--no-parallel`, `--parallel`, `--experimental-maximum-parallelization-width` as xcodebuild arguments | They belong to the `swift test` / Swift Testing entry point (`EntryPoint.swift`), and the doc cites `swift test --no-parallel`. `xcodebuild -help` has no such option. `CommandLineArguments` in an xctestrun go to the host app process [INFERENCE]. Use the env var path only (Q3). |
| `-retry-tests-on-failure`, `-test-iterations`, `-run-tests-until-failure`, `-test-repetition-relaunch-enabled` in the normal CI run | Multiply an 802 s run. Before Xcode 27, Swift Testing repetition covered "the entire test plan" (RN-27 fix wording). Relaunching the 260 MB host per repetition is slow [INFERENCE]. |
| `-enablePerformanceTestsDiagnostics` | "performance XCTests" only; there are none. |
| `-test-timeouts-enabled NO` | Removes hang protection (repo rule 15); gives no speed gain. Allowances below 60 s are not allowed by the plan UI. |
| `SWT_EXPERIMENTAL_SERIALIZED_TRAIT_APPLIES_GLOBALLY=1` | "Whether or not `.serialized` applies globally or just to its branch of the test graph": would serialize every `.uiGate` suite against all others. |
| `ENABLE_TESTABILITY=NO` for Debug test builds | "`-enable-testing` is passed to the Swift compiler" only when enabled; `@testable import` needs it. |
| `SWIFT_COMPILATION_MODE=wholemodule` for Debug as a speed fix | No official source claims it is faster; it would drop incremental builds ("Always rebuild all Swift source files in the module, in a single compiler process"). |
| `SWIFT_ENABLE_EXPLICIT_MODULES=NO` | Documented only as an opt-out "when encountering severe issues"; explicit modules are the default since 26 (RN-26). |
| `xccov merge` for the sharded gate | Needs separately exported `.xccovreport`/`.xccovarchive` pairs and "may be inaccurate for source files that changed"; `xcresulttool merge` kept and unioned coverage in the observed test. |
| Alternating `-enableCodeCoverage YES/NO` on one DerivedData path | RN-11.4 and the spec show instrumentation changes the build; every flip recompiles. |
| `-Xllvm -instrprof-atomic-counter-update-all` in the plain local loop | Clang manual: atomic updates are "accurate but ha[ve] overhead"; only needed for the coverage gate (repo rule 14). |
| `@response-file` in `-only-testing` on the Xcode 26.6 image | Seen only in Xcode 27.2 help/man; absent from all release notes (Not documented for 26.6). |
