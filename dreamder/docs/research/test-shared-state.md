# Process-wide state mutated by tests

Read-only audit of 2026-11-10 (`dreamder/DreamderTests` against the production declarations the tests mutate). All suites share one test-host process per shard and Swift Testing runs them concurrently, so a test that changes process-wide state can change what production code does inside another suite. Two CI failures of that night came from this class. Evidence is `path:line`; `[INFERENCE]` marks what was derived and not observed. The rows describe the code as it was audited. Status after the fixes of the same night: rows 1 to 6 and 8 are fixed (row 1: `AutosaveFlag` and `TestHost`, `AGENTS.md` rule 12; rows 2, 5 and 6: the merge automation addresses its own target workspace, the pending confirmation is task-local and the menu is injected; row 3: `DocumentRemovalContext` and parameterised entry points of `DreamderDocumentController`; row 4: the file scope and `SearchSettingsModel` take their `Settings`; row 8: window lists are parameters), rows 7 and 9 to 16 are open.

**Summary.** Tests are `@MainActor`, so a synchronous test body runs as one main-actor job and no other suite can interleave. This is derived from the sources below, not observed in a run:
- `Settings` is `@MainActor`, and the original `AutosavePreferenceTests` called `Settings(...)` synchronously without annotating itself.
- The target uses `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` (`Dreamder.xcodeproj/project.pbxproj:659`).

Interference therefore needs one of three things: a real suspension (`eventually`, `Task.sleep`, a git process), a non-main reader, or a second host process (shards).

Swift Testing documents `.serialized` as not helping across suites (`ParallelizationTrait.swift`, swift-testing): "This trait does not affect the execution of a test relative to its peers or to unrelated tests." `.uiGate` only caps concurrency at 3 suites (`UISuiteGate.swift:6`).

**State of the tree.** `AutosavePreference` was rewritten while the audit ran. The first read was `static let isEnabled = Mutex(false)`; the second was `AutosaveFlag`, `Settings(baseURL:autosaveFlag:)` and `Settings.processWideAutosaveFlag` (nil under `TestHost`). Row 1 covers both states.

**Row 1 detail.**
- Original state. `DreamderApp.swift:14` does `let settings = Settings.shared`, so the host initialised it at launch. `Settings.swift` (original `:39, :85-88`) wrote `isAutoSaveOn` into the flag, and `GeneralSettings.swift:66` defaults that to `true`. In tests, every `CodeFileDocument` without `autosavingInPlace = { false }` therefore autosaved in place.
- Why 2 s later. `scheduleAutosaving` is called from `updateChangeCount`, and the autosave fires after the sleep without re-reading the flag (`CodeFileDocument.swift:282-286`).
- Non-main readers. Apple documents that AppKit reads `autosavesInPlace` at various times "not always on the main thread" (NSDocument.autosavesInPlace). That explains the nonisolated `Mutex`, and why a short window is enough. That this is what failed on CI is `[INFERENCE]`.
- Current state. The flag stays `false` in the host. The per-document seam `autosavingInPlace` (`CodeFileDocument.swift:128`) is untouched. Tests that opt in with `{ true }` (`CodeFileDocumentCoverageTests:52`, `CodeFileDocumentStateTests:335`) stay per-instance.

## Checked and not found
- Not found in `DreamderTests`: `setenv`/`unsetenv`/`putenv`, `changeCurrentDirectoryPath`, `NSPasteboard.general` (only a private named board, `ProjectNavigatorDragDropTests:257`), and any write to `TreeSitterClient.Constants`. The only package-global use is a read (`TreeSitterClientEditCompletionTests.swift:56`).
- `ProcessSlotPool` tests use their own pools (`ProcessSlotPoolTests:47` etc.). `.shared` is only consumed (`GitMergeFixture.swift:33`).
- Safe by design: `SettingsScope.$current` and `MergeToolConfirmation.$override` (TaskLocal); `DreamderDocumentControllerCoverageTests.LastDocumentScope` (sync tests); the `appdelegate.` id prefix on the `.taskNotification` observers (`AppDelegateTests.swift:94`).

## The three globals that remove the most risk

1. **`MergeToolPresenter` "last…" statics (with `MergeAutomation` and `MergeToolConfirmation.automationAnswer`).**
   - Existing seams: `MergeToolPresenter.conflictsModel(for: workspace)` (`:40`), the keyed dictionaries (`:6-7`), `MergeAutomation.targetPath`, and `MergeToolConfirmation.$override`.
   - Smallest change: resolve the automation commands through those keyed lookups from `targetPath` and the path (adding a `revisionsModel(for:path:)`), instead of `conflictsModel`/`revisionsWindow`/`revisionsModel`. Make `automationAnswer` a TaskLocal like `override`.

2. **`DreamderDocumentController.shared` field swaps (`lspService`, `openDocuments`, `filePanels`, `settings`, `recentProjects`).**
   - Existing seam: the fields are already injectable, and the `removeDocument` logic reads only them.
   - Smallest change: extract the body of `removeDocument` (`:154-163`) into a function that takes the service, `openDocuments` and `settings` as parameters, so the tests call it directly and never mutate the singleton. The same applies to `newDocument`/`openDocument(nil)` with `panels:`, which already exists on `openDocument(onCompletion:onCancel:panels:)` (`:83`).

3. **`Settings.shared`.**
   - Existing seams: `Settings(baseURL:)`, `SettingsScope.current`, and the `settings:` parameter of `configureFileScope` (`WorkspaceDocument+FileScope.swift:5`).
   - Smallest change: use that `settings` parameter inside the `Observations` closure at `:17` instead of `Settings.shared`. `WorkspaceIndexTests` can then pass an isolated `Settings`. Do the same for `SearchSettingsModel.shared`, which hard-codes `Settings[\.search]` at `SearchSettingsModel.swift:20-22`. `AutosavePreference` is already handled by `AutosaveFlag`.
