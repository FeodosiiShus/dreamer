# dreamder

Native macOS code editor in Swift, forked from an MIT-licensed native editor (`LICENSE.md` keeps its notice), restyled and extended to look and work like IntelliJ IDEA's New UI (Islands Dark) and like Flint (`/Users/oleksandr/WebstormProjects/Flint`, the product reference). The bundled IntelliJ assets (expui icons, Islands themes, JetBrains Mono) come from the IntelliJ sources in this repository. CI: `.github/workflows/dreamder.yml` at the repository root runs `make check` on Ubuntu, then builds and tests on a matrix of `macos-26` with Xcode 26.6 (primary: coverage gate, Release app and dSYM artifacts) and `xcode-27` with Xcode 27.2.

## Rules

1. NEVER write comments or doc comments in new or edited code; leave existing comments alone.
2. Follow the existing patterns: every model is `@Observable` (`@MainActor` where it drives UI; `@ObservationIgnored` for weak refs, caches, tasks, cancellables and property wrappers such as `@AppSettings`); views own models with `@State`, take them as `let`, bind with `@Bindable`, and receive shared objects through `@Environment(Type.self)` injected with `.environment(_:)` (optional objects: `.environment(optional)` + `@Environment(Type.self) var x: Type?`); focused objects use `.focusedValue`/`@FocusedValue(Type.self)`. Cross-object reactions use `Observations { … }` loops in a stored `Task` cancelled in `isolated deinit` (debounce/throttle = cancel-and-restart `Task.sleep`); Combine stays only for `NotificationCenter`/`NSApp` publishers and subjects that are not derived from model state. Never introduce `ObservableObject`, `@Published`, `@StateObject`, `@ObservedObject`, `@EnvironmentObject`. Packages named `CodeEdit*` (`CodeEditSourceEditor`, `CodeEditTextView`, `CodeEditLanguages`, `CodeEditKit`, `CodeEditSymbols`) are third-party dependencies and keep their names.
3. Colors, metrics, and fonts of new chrome come from `Dreamder/Features/Islands/Islands.swift` (IntelliJ Islands Dark values). Icons are IntelliJ expui SVGs in `Dreamder/IntelliJIcons.xcassets`, addressed as `Image("<set>/<name>")` (for example `toolwindows/project_20`, `vcs/branch`, `general/search`); the full list is printed by `ls Dreamder/IntelliJIcons.xcassets/*/`.
4. Tool windows are identified by `ToolWindowID` and shown through `WorkspaceDocument.toolWindowManager` (`Dreamder/Features/Islands/ToolWindow.swift`).
5. Flint is GPL-3.0 and written in Rust: use it as a behavior and visual reference only, never copy its code or assets.
6. NEVER add a Swift package without user approval.
7. New files inside `Dreamder/`, `DreamderTests/`, and `DreamderUITests/` are picked up automatically (file-system synchronized groups); never hand-edit `project.pbxproj` to add files.
8. Deployment target is macOS 26.0. Every target compiles in Swift 6 language mode with strict and approachable concurrency; the app target has default `MainActor` isolation, test targets are nonisolated with `@MainActor` on suites that drive UI owners. Locally the SDK is macOS 27.2 with Swift 6.4; CI also compiles with Xcode 26.6 (SDK 26.5, Swift 6.3), so no macOS 27-only API without `#available` and no compiler features newer than Swift 6.3. `@State` with an initializer value must not be reassigned in `init`; assign non-`@State` stored properties first.
9. Crash-free code: `make check` (`Scripts/crash-guard.py`) fails on `fatalError`, `precondition`, `assert`, `assertionFailure`, `try!`, `as!`, force unwraps, implicitly unwrapped optionals, and `unowned`. Use `guard let`, failable `init?(coder:) { nil }`, optional outlets, and neutral fallbacks. `Scripts/crash-guard-allowlist.txt` is only for traps on programmer errors (dependency-injection registration); it must never grow for runtime input.
10. Subprocesses go through `Dreamder/Utils/Process/` (`ProcessRunner`, `ShellClient`, `GitCommandRunner`): argv arrays, sanitized environment, no shell string interpolation, no direct `Process()` in features. `ProcessRunner` takes a slot from `ProcessSlotPool.shared` (2× cores, minimum 4) for every child process so bursts (blame, gutters, git status) never fork-storm the machine; git write commands are additionally serialized per repository by `GitClient`. Never block a thread waiting for a child (`waitUntilExit`, `waitid`) outside a `@concurrent` function.
11. SwiftUI owns all chrome layout; AppKit appears only as leaves (`NSViewRepresentable` for the text view, terminal, outline view, menu anchors) or as window/panel/toolbar roots. NEVER put an `NSHostingView`/`NSHostingController` inside an AppKit container that itself lives inside SwiftUI (no `NSSplitViewController`, `NSTabViewController`, `NSStackView` or table-cell hosting under a representable): that sandwich oscillates between SwiftUI's ideal size and Auto Layout, AppKit logs `layoutSubtreeIfNeeded … has continued for 300 iterations` and then terminates the process. Splits are `Features/SplitView/` (pure SwiftUI `Layout` with IntelliJ `Splitter` semantics); a `Layout` that hosts representables NEVER measures its panes (`sizeThatFits` on a hosted AppKit view runs Auto Layout fitting-size and feeds back into SwiftUI), it sizes them from explicit `LayoutValueKey`s only. Every remaining hosting root sets `sizingOptions` explicitly: `[]` when the container sizes it (window content via `WorkspaceHostingController`, fixed-size panels), `.standardBounds` for toolbar leaves whose root view is `.fixedSize()` (min = ideal = max, so the toolbar measurement is unambiguous), `[.intrinsicContentSize]` for fixed-height table cells, `.preferredContentSize` for popovers. Guards: `WorkspaceWindowLayoutStabilityTests` (in-process), `make smoke` (headless app driven through the automation hooks; fails on process death, a new crash report, or AppKit layout-loop log lines) which CI runs on both macOS images.
12. Tests share one host process and Swift Testing runs suites concurrently, so anything that blocks the main thread stalls every suite (CI runners are 3–5× slower than a laptop: a 13 s local stall became a 54 s stall that timed out shell-task tests). Never pump `RunLoop.main.run`; await `Task.sleep`. Nested harness types inside a `@MainActor` suite need their own `@MainActor`. Heavy work that does not need the main thread (OSLogStore queries, file enumeration, git) goes through `nonisolated` `@concurrent` helpers: `AppKitLayoutLoopDetector.diagnostics(since:)` (one query at the end of a test, step attribution via `describe`) and `HostedSourceEditorFixture` (hosted `SourceEditor` with production coordinators) live in `DreamderTests/Helpers/`. Tests must not depend on installed language servers (sourcekit-lsp is present on CI and locally): use a plain-text fixture when a coordinator must see "no server".
13. Ported IntelliJ behavior is verified against IntelliJ's own test data from this repository, loaded at test time through `DreamderTests/Helpers/IntelliJTestData.swift` (`repositoryRoot`, `text(_:)`, `pairs(in:)`), never hand-copied into Swift literals: vcs-log graph fixtures (`platform/vcs-log/graph/testData/**`), diff/patch fixtures (`platform/platform-tests/testData/diff/**`), git widget-tree snapshots (`plugins/git4idea/testData/widgetTree/**`), find-in-editor goldens (`platform/lang-impl/testData/editor/findInEditor/*.gold`), Markdown token dumps and PSI dumps (`plugins/markdown/test/data/{highlighting,parser}/**`). IntelliJ tests whose cases are inline Kotlin/Java DSL (diff comparison, matchers, Markdown typing/actions) are ported case by case with the IntelliJ test name kept in the Swift test name. The `.md` fixtures of the Markdown plugin are absent from this checkout; inputs are reconstructed from PSI dumps where possible and the gap is stated in the test file.

## Commands

Run from `dreamder/`. `make` forces `DEVELOPER_DIR` to Xcode, because the command line tools lack the SwiftUI macros.

| Command | Purpose |
|---|---|
| `make check` | Run the crash guard over `Dreamder/` (pure Python, no build). CI runs it first. |
| `make build` | Resolve packages, stub the SwiftLint build plugin (its binary cannot load sourcekitd under Xcode 27), build the Debug app into `.build/xcode`. Prints only errors and the result; the full log is `.build/logs/build.log`. |
| `make run PROJECT_DIR=<folder>` | Build, quit the running copy, and open `<folder>` (default: this directory) in the app, visibly. For the user only; agents use `make headless`. |
| `make headless PROJECT_DIR=<folder>` | Build, quit the running copy, and open `<folder>` in headless mode: no Dock icon, never activates or steals focus, every window lives off-screen. All automation below works the same; screenshots capture the off-screen windows. |
| `make open FILE=<path>[:line:column]` | Open a file of an already open project in the running app's editor, optionally with the caret at a 1-based line and column (for screenshots). |
| `make toolwindow ID=<id>` | Show a tool window (`project`, `commit`, `structure`, `run`, `find`, `terminal`, `problems`, `git`, `languageServices`) in the frontmost project window of the running app. |
| `make screenshot [OUT=<dir>]` | Ask the running app to save PNGs of its windows (popups included) into `<dir>` (default `.build/screenshots/latest`). Works without Screen Recording permission. |
| `make action NAME=<selector>` | Send an action selector (for example `openSearchEverywhere:`) through the responder chain of the running app, then use `make screenshot` to see the result. |
| `make contextmenu [OUT=<dir>]` | Synthesize a right-click at the caret of the active editor, call the text view's context menu and dump the resulting menu items (recursively, with enabled state and shortcuts) into `<dir>/contextmenu.txt` (default `.build/contextmenu`). |
| `make annotate [OUT=<dir>]` | Toggle the Git blame annotation column of the active editor and write the new mode into `<dir>/annotate.txt` (default `.build/annotate`), then use `make screenshot` to see it. |
| `make menuitem NAME="Show History" [OUT=<dir>]` | Build the active editor's context menu and perform the item with that title (submenus included); reports whether the action was handled and lists the app's visible windows in `<dir>/menuitem.txt` (default `.build/menuitem`). |
| `make merge CMD="<command>[:<arg>...]"` | Drive the merge tool headlessly: `conflicts[:<project path>]`, `select:<path>`, `selectAdd:<path>`, `selectRange:<path>`, `acceptYours`, `acceptTheirs`, `mergeSelected`, `mergeFile:<path>`, `resolve:<block>:<left\|right\|ignored>`, `clickChip:<left\|result\|right>:<block>:<left\|right\|ignore>`, `applyNonConflicting:<left\|all\|right>`, `editResult:<text>`, `acceptLeft`, `acceptRight`, `apply`, `cancel`, `closeRevisions`, `closeConflicts`, `confirm:<yes\|no>`, `dump:<dir>` (writes `<dir>/merge.txt`). |
| `make release` | Build the Release configuration (ad-hoc signed) and zip it into `.build/Dreamder.zip`; this is what CI uploads. |
| `make test [FILTER=<Suite>]` | Run the `DreamderTests` unit tests (or one suite/class) with the test host in headless mode. Swift Testing suites run concurrently inside the test host; only suites with shared global state are `.serialized`. Full log in `.build/logs/test.log`. |
| `make coverage [TOP=<n>] [COVERAGE_CHECK=1]` | Run the unit tests headlessly with code coverage, then print per-file line coverage of the app sources in `Dreamder/` (lowest first, last `<n>` lines, default 40) and the total. Full table in `.build/logs/coverage.txt`, JSON in `.build/coverage.json`. With `COVERAGE_CHECK=1` (CI primary job) it fails when coverage drops below `Scripts/coverage-baseline.json` by scope (`Scripts/coverage-scopes.json`: `pure`, `viewModel`, `io` gated; `view` reported). |
| `make coverage-baseline` | Rewrite `Scripts/coverage-baseline.json` from the last `make coverage` run for the local gate; the file records the Swift toolchain and the gate enforces only on that toolchain. CI does not use this file: each matrix job uploads its own `coverage-baseline-<runner>` artifact and gates against the artifact of the previous successful run on the same runner (first green run only reports). Commit the local file when coverage legitimately moves. |
| `make ui-test [ONLY=DreamderUITests/<Class>/<method>]` | Run UI tests. |
| `make smoke` | System test: builds, launches the app headlessly on a temporary fixture project and drives it through the automation hooks (open file, split the editor right/down/right, every tool window, Search Everywhere, branches popup, toolbar toggle); fails if the process dies, a new `Dreamder*.ips` crash report appears, or the AppKit log shows a layout loop. Screenshots and `smoke.log` land in `.build/smoke/`. CI runs it on both macOS images after the unit tests. |

Testing is headless: agents NEVER run `make run`, `make ui-test`, or `open -a` on the app without `make headless`, so nothing appears on the user's screen. Only one build or test command may run at a time: they share `.build/xcode`. Unit tests write settings into a temporary directory, never into `~/Library/Application Support/Dreamder`.
