# dreamder

Native macOS code editor in Swift, forked from an MIT-licensed native editor (`LICENSE.md` keeps its notice), restyled and extended to look and work like IntelliJ IDEA's New UI (Islands Dark) and like Flint (`/Users/oleksandr/WebstormProjects/Flint`, the product reference). The bundled IntelliJ assets (expui icons, Islands themes, JetBrains Mono) come from the IntelliJ sources in this repository. CI: `.github/workflows/dreamder.yml` at the repository root runs `make check` on Ubuntu, builds the Release app and dSYM artifacts on `macos-26`, and calls the reusable `.github/workflows/dreamder-platform.yml` once per platform: `macos-26` with Xcode 26.6 and `xcode-27` with Xcode 27.2 (the only GitHub-hosted label with macOS 27; its default Xcode is 27.1, so the workflow sets `DEVELOPER_DIR`). Per platform the pipeline is one instrumented `make build-for-testing` plus `make lint`, then in parallel the test shard jobs (one runner per shard, `make test-shard` on the downloaded test products) and the headless smoke job, then the coverage gate job that merges the shard result bundles (`make coverage-merge`). The shard list is the `shards` input of the reusable workflow; the caller passes `[0, 1]`, because GitHub runs at most five macOS jobs at once on Free, Pro and Team plans and two test jobs per platform plus the smoke and release jobs fit that limit. The CI test jobs pass `TIME_ALLOWANCE=600` (`xcodebuild -default-test-execution-time-allowance`): the hosted three-core runners are about 2.4 times slower than a developer machine, so tests queued behind the UI gate outlive the test plan's 120 s default there (run 42706519487 failed that way with one shard). Research behind the CI and build setup, the Swift production-readiness checklist and the bug audit are in `docs/research/`.

## Rules

1. NEVER write comments or doc comments in new or edited code; leave existing comments alone.
2. Follow the existing patterns: every model is `@Observable` (`@MainActor` where it drives UI; `@ObservationIgnored` for weak refs, caches, tasks, cancellables and property wrappers such as `@AppSettings`); views own models with `@State`, take them as `let`, bind with `@Bindable`, and receive shared objects through `@Environment(Type.self)` injected with `.environment(_:)` (optional objects: `.environment(optional)` + `@Environment(Type.self) var x: Type?`); focused objects use `.focusedValue`/`@FocusedValue(Type.self)`. Cross-object reactions use `Observations { … }` loops in a stored `Task` cancelled in `isolated deinit` (debounce/throttle = cancel-and-restart `Task.sleep`); Combine stays only for `NotificationCenter`/`NSApp` publishers and subjects that are not derived from model state. Never introduce `ObservableObject`, `@Published`, `@StateObject`, `@ObservedObject`, `@EnvironmentObject`. Packages named `CodeEdit*` (`CodeEditSourceEditor`, `CodeEditTextView`, `CodeEditLanguages`, `CodeEditKit`, `CodeEditSymbols`) are third-party dependencies and keep their names.
3. Colors, metrics, and fonts of new chrome come from `Dreamder/Features/Islands/Islands.swift` (IntelliJ Islands Dark values). Icons are IntelliJ expui SVGs in `Dreamder/IntelliJIcons.xcassets`, addressed as `Image("<set>/<name>")` (for example `toolwindows/project_20`, `vcs/branch`, `general/search`); the full list is printed by `ls Dreamder/IntelliJIcons.xcassets/*/`.
4. Tool windows are identified by `ToolWindowID` and shown through `WorkspaceDocument.toolWindowManager` (`Dreamder/Features/Islands/ToolWindow.swift`).
5. Flint is GPL-3.0 and written in Rust: use it as a behavior and visual reference only, never copy its code or assets.
6. NEVER add a Swift package without user approval.
7. New files inside `Dreamder/`, `DreamderTests/`, and `DreamderUITests/` are picked up automatically (file-system synchronized groups); never hand-edit `project.pbxproj` to add files.
8. Deployment target is macOS 26.0. Every target compiles in Swift 6 language mode with strict and approachable concurrency; the app target has default `MainActor` isolation, test targets are nonisolated with `@MainActor` on suites that drive UI owners. Locally the SDK is macOS 27.2 with Swift 6.4; CI also compiles with Xcode 26.6 (SDK 26.5, Swift 6.3), so no macOS 27-only API without `#available` and no compiler features newer than Swift 6.3. `@State` with an initializer value must not be reassigned in `init`; assign non-`@State` stored properties first.
9. Crash-free code: `make check` (`Scripts/crash-guard.py`) fails on `fatalError`, `precondition`, `assert`, `assertionFailure`, `try!`, `as!`, force unwraps, implicitly unwrapped optionals, and `unowned`. Use `guard let`, failable `init?(coder:) { nil }`, optional outlets, and neutral fallbacks. `Scripts/crash-guard-allowlist.txt` is only for traps on programmer errors and for protocol requirements that must repeat an AppKit implicitly unwrapped declaration (today only `FilePanelConfiguring`/`SavePanelConfiguring`, so `NSOpenPanel`/`NSSavePanel` conform); it must never grow for runtime input. The language server service is the typed shared instance `LSPService.shared` (no service container); injectable seams that need a no-service branch take `LSPService?`/`() -> LSPService?` defaulting to `.shared`.
10. Subprocesses go through `Dreamder/Utils/Process/` (`ProcessRunner`, `ShellClient`, `GitCommandRunner`): argv arrays, sanitized environment, no shell string interpolation, no direct `Process()` in features. `ProcessRunner` takes a slot from `ProcessSlotPool.shared` (2× cores, minimum 4) for every child process so bursts (blame, gutters, git status) never fork-storm the machine; git write commands are additionally serialized per repository by `GitClient`. Never block a thread waiting for a child (`waitUntilExit`, `waitid`) outside a `@concurrent` function.
11. SwiftUI owns all chrome layout; AppKit appears only as leaves (`NSViewRepresentable` for the text view, terminal, outline view, menu anchors) or as window/panel/toolbar roots. NEVER put an `NSHostingView`/`NSHostingController` inside an AppKit container that itself lives inside SwiftUI (no `NSSplitViewController`, `NSTabViewController`, `NSStackView` or table-cell hosting under a representable): that sandwich oscillates between SwiftUI's ideal size and Auto Layout, AppKit logs `layoutSubtreeIfNeeded … has continued for 300 iterations` and then terminates the process. Splits are `Features/SplitView/` (pure SwiftUI `Layout` with IntelliJ `Splitter` semantics); a `Layout` that hosts representables NEVER measures its panes (`sizeThatFits` on a hosted AppKit view runs Auto Layout fitting-size and feeds back into SwiftUI), it sizes them from explicit `LayoutValueKey`s only. Every remaining hosting root sets `sizingOptions` explicitly: `[]` when the container sizes it (window content via `WorkspaceHostingController`, fixed-size panels), `.standardBounds` for toolbar leaves whose root view is `.fixedSize()` (min = ideal = max, so the toolbar measurement is unambiguous), `[.intrinsicContentSize]` for fixed-height table cells, `.preferredContentSize` for popovers. Guards: `WorkspaceWindowLayoutStabilityTests` (in-process), `make smoke` (headless app driven through the automation hooks; fails on process death, a new crash report, or AppKit layout-loop log lines) which CI runs on both macOS images.
12. Tests share one host process and Swift Testing runs suites concurrently, so anything that blocks the main thread stalls every suite (CI runners are 3–5× slower than a laptop: a 13 s local stall became a 54 s stall that timed out shell-task tests). Never pump `RunLoop.main.run`; await `Task.sleep`. A nested run loop inside a main-actor job (`Process.waitUntilExit`, `NSAlert.runModal`, `NSApp.runModal`) never drains the main queue, so every other main-actor test freezes until it returns: child processes in tests go through `@concurrent async` helpers (`GitMergeFixture`) and are awaited. Nested harness types inside a `@MainActor` suite need their own `@MainActor`. Heavy work that does not need the main thread (OSLogStore queries, file enumeration, git) goes through `nonisolated` `@concurrent` helpers: `AppKitLayoutLoopDetector.diagnostics(since:)` (one query at the end of a test, step attribution via `describe`) and `HostedSourceEditorFixture` (hosted `SourceEditor` with production coordinators) live in `DreamderTests/Helpers/`. Tests must not depend on installed language servers (sourcekit-lsp is present on CI and locally): use a plain-text fixture when a coordinator must see "no server". Never touch `NSPasteboard` (the general board or `withUniqueName()`) from tests or eagerly on an action path: on CI runners the first pasteboard-server connection blocked the main thread for 60 s and froze every suite; production reads the pasteboard lazily and only for the command that needs it. The seam is `PasteboardAccess` (`Utils/Pasteboard/`): its live implementation `SystemPasteboard` resolves `NSPasteboard.general` per call, production types take `any PasteboardAccess = SystemPasteboard()` (About subtitle, editor context menu, tab bar item actions, breadcrumbs, project navigator clipboard and copy-path), and tests inject `InMemoryPasteboard` (`DreamderTests/Utils/`); drag and drop is tested through `ProjectNavigatorViewController.acceptDrop(of:sourceOperationMask:onto:)`/`dropOperation(in:proposedItem:proposedChildIndex:sourceOperationMask:)`, the `NSDraggingInfo` methods only extract the URLs and mask. `DreamderWindowController.markdownClipboard` stays the injectable closure reader of the Markdown paste. `DreamderDocumentController` skips `noteNewRecentDocument(URL)` and `RecentsStore.documentOpened` in headless mode: AppKit's recent-documents insert goes through `sharedfilelistd`, which blocked the CI main thread for 60 s on the first document open (`Insert failed for list identifier com.apple.LSSharedFileList.RecentDocuments` in the log is the signature), and the WelcomeWindow package resolves every security-scoped bookmark over XPC on the main thread each time its list changes (3 s for 100 entries). To find a stall, run `TEST_RUNNER_DREAMDER_STALL_SAMPLE_DIR=$PWD/.build/logs/stalls make test`: `MainThreadStallSampler` writes a `/usr/bin/sample` report of the whole process into that directory the moment the main thread stops heartbeating for 3 s; the first `Thread_… main-thread` section names the blocking frame. Test helpers that every test calls never walk bridged strings in Swift: `removeDefaultsKeys`/`StaleTestDefaults.purge()` (`DreamderTests/Utils/withTempDir.swift`) match defaults keys through `NSString.range(of:options:)`, because `String.contains` on keys bridged from `UserDefaults` takes the slow non-contiguous path and held the main thread in 54 of 120 stall samples. A long-lived host slows down as it runs: the same suite took 757 s in one host, 471 s when the host was restarted after four minutes and 245 s in three hosts (`docs/research/README.md`). On CI the test shard jobs use a sparse checkout (job `test` in `.github/workflows/dreamder-platform.yml`): every IntelliJ fixture directory a test reads must be listed there.
13. Ported IntelliJ behavior is verified against IntelliJ's own test data from this repository, loaded at test time through `DreamderTests/Helpers/IntelliJTestData.swift` (`repositoryRoot`, `text(_:)`, `pairs(in:)`, `files(in:suffix:)`, `url(_:)`), never hand-copied into Swift literals: vcs-log graph fixtures (`platform/vcs-log/graph/testData/**`), diff/patch fixtures (`platform/platform-tests/testData/diff/**`, also for partial-commit patches), git widget-tree snapshots (`plugins/git4idea/testData/widgetTree/**`), find-in-editor goldens (`platform/lang-impl/testData/editor/findInEditor/*.gold`), Markdown token dumps and PSI dumps (`plugins/markdown/test/data/{highlighting,parser}/**`), multi-caret editor actions (`platform/platform-tests/testData/editor/multiCaret/**`), comment-by-line/block fixtures (`java/java-tests/testData/codeInsight/{commentByLine,commentByBlock}`, `xml/tests/testData/codeInsight/{commentByLine,commentByBlock}`, `platform/platform-tests/testData/codeInsight/commentByLine/pl`, `json/backend/tests/testData/commenter`), join lines (`java/java-tests/testData/codeInsight/joinLines`, `python/testData/joinLines`), move statement (`java/java-tests/testData/codeInsight/moveStatementAction`), select word (`platform/platform-tests/testData/codeInsight/{selectWordAction,selectWordWithoutPSIAction}`), and the Mac/default keymaps (`platform/platform-resources/src/keymaps`). Every directory a test reads must be listed in the CI sparse checkout (job `test` in `.github/workflows/dreamder-platform.yml`). IntelliJ tests whose cases are inline Kotlin/Java DSL (diff comparison, matchers, Markdown typing/actions) are ported case by case with the IntelliJ test name kept in the Swift test name. The `.md` fixtures of the Markdown plugin are absent from this checkout; inputs are reconstructed from PSI dumps where possible and the gap is stated in the test file.
14. Law: every line of `Dreamder/` is covered by tests, like SQLite — 100 % in every scope, views included. Nothing is exempt: SwiftUI bodies render in the headless test host through `DreamderTests/Helpers/HostedViewFixture.swift` with every state variant exercised, AppKit controllers through real headless windows, io through temp directories and fakes injected at the constructor. Code that cannot be reached by any test is dead and is deleted (with the user's approval), never left uncovered. The coverage gate fails when any file or the total is below 100 % (see `make coverage`). The gate reads `xccov view --report`, which counts every closure, autoclosure and default-argument expression as its own region: a `?? fallback`, a button action closure, `x[...]` (an unexecuted `UnboundedRange` operator reference) or a default argument nobody evaluates is uncovered even when its line ran; `xcrun xccov view --archive --json --file <path> .build/coverage.xcresult` lists the zero-count `subranges`. Impossible states are made unrepresentable (non-optional/non-empty types, typed throws, `ArraySlice(x)`, an injected collaborator for an external failure) rather than guarded by a fallback no test can reach; a view action becomes a named method the view calls; `.debug` log interpolations are never evaluated in the test host, so logs use `.info` or higher; commands registered on shared singletons resolve their store through `SettingsScope.current ?? .shared` so tests run them against an isolated `Settings`. Coverage must not depend on timing or chance: every branch is reached by a test written for it (a race-dependent loop is extracted into a pure helper driven with fakes), randomized tests use the seeded `SeededRandomNumberGenerator` (`DreamderTests/Utils/`), and `make test`/`make coverage`/the sharded runs set `SWIFT_DETERMINISTIC_HASHING=1` for the test host (`stdlib/public/runtime/EnvironmentVariables.def` in swiftlang/swift: "Disable randomized hash seeding"), so `Set`/`Dictionary` iteration order is the same in every run. Coverage builds (`make coverage`, `make coverage-sharded`) add `-Xllvm -instrprof-atomic-counter-update-all` to `OTHER_SWIFT_FLAGS`: Swift Testing runs tests in parallel, non-atomic profile counters lose increments, and LLVM derives branch counts as counter differences, so a lost increment on a hot counter shows a once-hit branch as uncovered. Fake language servers written as shell scripts keep stdout open after replying (`cat > /dev/null`, never `exec cat > /dev/null`), otherwise the client sees `dataStreamClosed`.
15. Test-host load is bounded: every `@MainActor` suite carries the `.uiGate` suite trait (`DreamderTests/Utils/UISuiteGate.swift`, `@Suite(.serialized, .uiGate)`), which lets only three UI suites run at once. Swift Testing starts every test at once and the time limit (120 s, `DreamderTestPlan.xctestplan`) wraps each test case but not suite scopes, so the gate sits at suite level; without it thousands of main-actor tests interleave on the one main thread, cooperative threads block in package code that hops to main (`DispatchQueue.waitMainIfNot` in CodeEditTextView, SwiftTerm's `LocalProcess`), and whole runs time out. SwiftUI `Button`s render without any `NSButton` on macOS 27 (no accessibility children either), so tests never look for `NSButton` inside SwiftUI content: command and menu content is driven through `NSHostingMenu(rootView:)` (`menu.update()`, item titles/`isEnabled`/`keyEquivalent`/`state`, `performActionForItem(at:)`; `DreamderTests/Features/WindowCommands/CommandsACoverageSupport.swift`), other views keep each button action a single call to a model method that tests call directly while the view is rendered for coverage. Production never constructs `NSOpenPanel`/`NSSavePanel` directly (constructing one blocks the test host's main thread on the remote panel bridge): it goes through `FilePanelPresenting` (`Utils/FilePanels/`, live `SystemFilePanels` answers cancel in headless mode and records the request in `DreamderHeadless.suppressedModals`), tests inject `FakeFilePanels`; `SystemFilePanels` itself takes its panel factories (default `NSOpenPanel.init`/`NSSavePanel.init` as function references, not closure bodies) and the headless check as stored closures, so its tests run the real non-headless path on fake panels. Every system boundary has this shape — an injected factory or closure whose default is an Apple API reference — so no line of `Dreamder/` is untestable. Tests never use per-test unique `UserDefaults` suites (cfprefsd leaves a plist behind for each): `.isolatedDefaults`, `makeIsolatedDefaults()` and `PooledDefaults` hand out a bounded pool; `withTempDir` removes every `UserDefaults.standard` key that mentions its directory, and the `.uiGate` trait runs `StaleTestDefaults.purge()` after every gated suite, removing standard-domain keys that point at temporary paths which no longer exist: windows, outline views and documents still write `workspaceState-…`, `NSOutlineView Items …` and `dreamder.recentFiles.…` keys after a test's directory is gone, and once the `dev.dreamder.Dreamder` domain passes the 4 MB CFPreferences limit the test host is killed (`Crash: Dreamder` with no crash report). Tests never write `Settings.shared`: every suite shares the host with hundreds of concurrent suites, so a temporary preference flip (autosave, ignore globs, terminal shell) changes their behaviour mid-test. Hosted views get an isolated `Dreamder.Settings(baseURL: <temp dir>)` through `.environment(\.settingsStore, store)` (read by `@AppSettings`), detached view values through the task-local `SettingsScope.$current.withValue(store)`, and models take the store as an initializer dependency defaulting to `.shared` (lazily, never evaluated while `Settings.shared` itself initialises). Arrays are indexed in tests only through `#require`, because an out-of-range subscript kills the shared host and every in-flight test.

## Commands

Run from `dreamder/`. `make` forces `DEVELOPER_DIR` to Xcode, because the command line tools lack the SwiftUI macros.

| Command | Purpose |
|---|---|
| `make check` | Run the crash guard over `Dreamder/` and `OpenWithDreamder/` (pure Python, no build). CI runs it first. |
| `make build` | Resolve packages only when `Package.resolved` changed since the last resolution (`Scripts/resolve-packages.sh` keeps a stamp next to `SourcePackages`), replace the SwiftLint build-plugin binary with a no-op stub (inside the plugin it crashes loading `sourcekitdInProc` under Xcode 27; the real binary is kept as `swiftlint.real` for `make lint`), build the Debug app into `.build/xcode`. The project's own targets treat Swift and C warnings as errors (`SWIFT_TREAT_WARNINGS_AS_ERRORS`/`GCC_TREAT_WARNINGS_AS_ERRORS` in the target build settings; package targets are unaffected). Prints only errors and the result; the full log is `.build/logs/build.log`. Build flavors never share a DerivedData directory: plain builds (`build`, `test`, `test-sharded`, `run`, `headless`, `smoke`, `release`) use `.build/xcode`, instrumented builds (`coverage`, `coverage-sharded` and every target run with `FLAVOR=coverage`) use `.build/xcode-coverage`, so alternating between tests and coverage never recompiles the other flavor. |
| `make build-for-testing [FLAVOR=coverage]` | Build the app and the test bundles of the selected flavor without running them; log in `.build/logs/build-for-testing.log`. CI runs it once per platform with `FLAVOR=coverage` and reuses the products for the shard, coverage and smoke jobs. |
| `make lint` | Run the real SwiftLint (`Scripts/swiftlint.sh`) from the shell over `Dreamder/`, `DreamderTests/` and `OpenWithDreamder/` with `.swiftlint.yml`, `--strict` and the baseline `Scripts/swiftlint-baseline.json`: any violation not in the baseline fails. CI runs it in the build job after `make build-for-testing`. |
| `make lint-baseline` | Rewrite `Scripts/swiftlint-baseline.json` from the current sources (only to absorb existing debt; new code fixes its violations instead). |
| `make run PROJECT_DIR=<folder>` | Build, quit the running copy, and open `<folder>` (default: this directory) in the app, visibly. For the user only; agents use `make headless`. |
| `make headless PROJECT_DIR=<folder>` | Build, quit the running copy, and open `<folder>` in headless mode: no Dock icon, never activates or steals focus, every window lives off-screen. All automation below works the same; screenshots capture the off-screen windows. |
| `make open FILE=<path>[:line:column]` | Open a file of an already open project in the running app's editor, optionally with the caret at a 1-based line and column (for screenshots). |
| `make toolwindow ID=<id>` | Show a tool window (`project`, `commit`, `structure`, `run`, `find`, `terminal`, `problems`, `git`, `languageServices`) in the frontmost project window of the running app; `ID=hide:<id>` hides it and `ID=toggle:<id>` toggles it (used to profile tool-window show/hide). |
| `make screenshot [OUT=<dir>]` | Ask the running app to save PNGs of its windows into `<dir>` (default `.build/screenshots/latest`): `window-<i>.png` with child windows that overlap the parent composited, and every child popup also alone as `window-<i>-popup-<j>.png`. Windows are made opaque for the capture (headless windows are fully transparent) and restored afterwards. Works without Screen Recording permission. |
| `make action NAME=<selector>` | Send an action selector (for example `openSearchEverywhere:`) through the responder chain of the running app, then use `make screenshot` to see the result. |
| `make contextmenu [OUT=<dir>]` | Synthesize a right-click at the caret of the active editor, call the text view's context menu and dump the resulting menu items (recursively, with enabled state and shortcuts) into `<dir>/contextmenu.txt` (default `.build/contextmenu`). |
| `make annotate [OUT=<dir>]` | Toggle the Git blame annotation column of the active editor and write the new mode into `<dir>/annotate.txt` (default `.build/annotate`), then use `make screenshot` to see it. |
| `make menuitem NAME="Show History" [OUT=<dir>]` | Build the active editor's context menu and perform the item with that title (submenus included); reports whether the action was handled and lists the app's visible windows in `<dir>/menuitem.txt` (default `.build/menuitem`). |
| `make merge CMD="<command>[:<arg>...]"` | Drive the merge tool headlessly: `conflicts[:<project path>]`, `select:<path>`, `selectAdd:<path>`, `selectRange:<path>`, `acceptYours`, `acceptTheirs`, `mergeSelected`, `mergeFile:<path>`, `resolve:<block>:<left\|right\|ignored>`, `clickChip:<left\|result\|right>:<block>:<left\|right\|ignore>`, `applyNonConflicting:<left\|all\|right>`, `editResult:<text>`, `acceptLeft`, `acceptRight`, `apply`, `cancel`, `closeRevisions`, `closeConflicts`, `confirm:<yes\|no>`, `dump:<dir>` (writes `<dir>/merge.txt`). |
| `make release` | Build the Release configuration (ad-hoc signed) and zip it into `.build/Dreamder.zip`; this is what CI uploads. |
| `make test [FILTER="<Suite> [<Suite> …]"]` | Run the `DreamderTests` unit tests (or the listed suites/classes, separated by spaces) with the test host in headless mode. Swift Testing suites run concurrently inside the test host; only suites with shared global state are `.serialized`. Full log in `.build/logs/test.log`. |
| `make coverage [TOP=<n>] [COVERAGE_CHECK=1]` | Run the unit tests headlessly with code coverage from the instrumented flavor (`.build/xcode-coverage`), then print per-file line coverage of the app sources in `Dreamder/` (lowest first, last `<n>` lines, default 40) and the total. Full table in `.build/logs/coverage.txt`, JSON in `.build/coverage.json`. With `COVERAGE_CHECK=1` (CI runs `Scripts/coverage-report.py --check`) the gate is absolute: it fails when any file in `Dreamder/` or the total is below 100 %, or a file is missing from `Scripts/coverage-scopes.json`, and names the uncovered lines; baselines are only used to print deltas. Coverage is counted in distinct executable lines read from the bundle's archive (`xccov view --archive --json`), not from the function-level report: in a bundle written by `xcresulttool merge` the report lists some functions a second time as uncovered (a three-shard run read 99.94 % there while every line of those files had run), the line data is the exact union of the shards. |
| `make coverage-baseline` | Rewrite `Scripts/coverage-baseline.json` from the last `make coverage` run; the file records the Swift toolchain and is used only for the deltas printed in the summary, never to pass or fail the gate. CI does not use this file when a previous successful run exists: each matrix job uploads its own `coverage-baseline-<runner>` artifact and prints deltas against the artifact of the previous successful run on the same runner, looked up on the PR head branch (`github.head_ref`) or the pushed branch, falling back to the PR base branch. |
| `make test-sharded [SHARDS=<n>]` | Fast local full run: `build-for-testing`, then `Scripts/sharded-tests.py` partitions the suites by test count (main-actor suites weighted ×3) and runs `<n>` (default 3) headless test hosts at once with `xcodebuild test-without-building -xctestrun` (no project or package work per shard) and `TEST_RUNNER_DREAMDER_SHARD=<i>` (per-shard `Settings.defaultBaseURL()` and isolated-defaults pool), then merges the bundles into `.build/sharded.xcresult`. Shards `0…n-2` get `-only-testing` lists and the last shard skips everything the others own, so a suite the partitioner does not know still runs exactly once. Logs: `.build/logs/build-for-testing.log`, `.build/logs/shard-<i>.log`; a failed shard prints its `✘` lines. Measured on an M1 Pro: about 250 s for the whole suite (10 200 tests) in three hosts against 757 s in one host. |
| `make coverage-sharded [SHARDS=<n>] [TOP=<n>] [COVERAGE_CHECK=1]` | `make test-sharded` on the instrumented flavor; the merged bundle becomes `.build/coverage.xcresult` and the same report as `make coverage` is printed and written. With `COVERAGE_CHECK=1` the same absolute gate runs on the merged bundle, which makes this the fast local gate. Fails if the sharded run, the coverage report or the gate fails. |
| `make test-shard SHARD=<i> SHARDS=<n> [FLAVOR=coverage] [TIME_ALLOWANCE=<seconds>]` | Run one shard from existing test products, without building: result `.build/shards/shard-<i>.xcresult`, log `.build/logs/shard-<i>.log`. This is the CI test job. `TIME_ALLOWANCE` (also for `test-sharded` and `coverage-sharded`) replaces the test plan's 120 s default per-test allowance through `xcodebuild -default-test-execution-time-allowance`; the plan's 600 s maximum still applies. |
| `make coverage-merge` | Merge `.build/shards/shard-*.xcresult` into `.build/coverage.xcresult` and print the coverage report; the CI coverage job runs it before the gate. |
| `make pack-test-products` / `make unpack-test-products` `[TEST_PRODUCTS=<file>]` | Pack `Build/Products/<configuration>` and the `.xctestrun` of the selected flavor into a `tar --zstd` archive (default `.build/test-products.tar.zst`), or unpack one; CI hands the build to the test and smoke jobs this way. A DerivedData directory cannot be renamed and rebuilt (package plug-in paths inside it are absolute), but its products run through `-xctestrun` from any location. |
| `make ui-test [ONLY=DreamderUITests/<Class>/<method>]` | Run UI tests. |
| `make smoke` | System test: builds (skipped with `SMOKE_SKIP_BUILD=1`), launches the app headlessly on a temporary fixture project and drives it through the automation hooks (open file, split the editor right/down/right, every tool window, Search Everywhere, branches popup, toolbar toggle); fails if the process dies, a new `Dreamder*.ips` crash report appears, or the AppKit log shows a layout loop. Screenshots and `smoke.log` land in `.build/smoke/`. CI runs it on both platforms against the downloaded test products (`FLAVOR=coverage`, `SMOKE_SKIP_BUILD=1`), in parallel with the test shards. |

Testing is headless: agents NEVER run `make run`, `make ui-test`, or `open -a` on the app without `make headless`, so nothing appears on the user's screen. The guarantee is enforced at the AppKit level by `DreamderHeadless` (installed in `DreamderApp.init`, before launch completes): `.accessory` activation policy, `activate` no-ops, and every ordered window gets three barriers before `orderWindow:` runs — level `.minimumWindow` (below the WindowServer backstop; `desktopWindow − 1` was NOT enough: it sits above the Wallpaper layer and the windows were visible on the desktop), `alphaValue = 0`, and a frame outside every screen (`constrainFrameRect:toScreen:` is bypassed for off-screen frames; `.transient`/`.ignoresCycle`/`.stationary` keep them out of Exposé and ⌘⇥). WindowServer therefore does not list them as on-screen at all (`HeadlessTestHostTests.orderedWindowsNeverReachAnyScreen`), while AppKit/SwiftUI still lay out and render them (`hiddenWindowsStillRenderForSnapshots`; screenshots use `CGWindowListCreateImage` with an in-process `cacheDisplay` fallback). The following are replaced by recording no-ops — `NSAlert.runModal`/`beginSheetModal`, `NSSavePanel`/`NSOpenPanel` `runModal`/`begin`/`beginSheetModal` (answer `.cancel`), `NSApplication.runModal(for:)` (answers `.abort`), `NSWorkspace.open`/`activateFileViewerSelecting`/`selectFile`/`openApplication` (`suppressedModals` and `suppressedExternalOpens` keep the evidence for tests). `HeadlessTestHostTests` proves each interception; a test may call any of these APIs only through that proof. A test double for the document controller must implement `AppDocumentControlling`, never subclass `NSDocumentController`: `NSDocumentController.init()` returns the shared singleton, so a "stub" subclass drives the real controller (this is how an `NSOpenPanel` once reached the screen). Only one build or test command may run at a time: they share `.build/xcode`. Unit tests write settings into a temporary directory, never into `~/Library/Application Support/Dreamder`.
